# 동기 처리와 비동기 처리

## 동기 처리 (Synchronous)

**사용하면 좋은 경우:**
- **즉각적인 결과가 필요한 경우**: 계산, 데이터 변환 같이 빠르게 끝나는 작업
- **순서가 중요한 작업**: A 작업이 끝나야 B 작업을 할 수 있는 의존성이 있을 때
- **간단한 로직**: 코드가 위에서 아래로 순차적으로 실행되므로 이해하기 쉬움
- **에러 처리가 명확해야 할 때**: try-catch로 즉시 처리 가능

**예시**: 배열 정렬, 사용자 입력값 검증, 로컬 파일 읽기(동기 API)

---

## 비동기 처리 (Asynchronous)

**사용하면 좋은 경우:**
- **시간이 걸리는 I/O 작업**: 네트워크 요청, 데이터베이스 쿼리, 파일 읽기/쓰기
- **블로킹을 피해야 할 때**: 서버 요청 기다리는 동안 다른 작업을 계속 처리하고 싶을 때
- **여러 작업을 병렬로 처리**: 여러 API를 동시에 호출해야 할 때 (Promise.all 등)
- **사용자 경험**: 웹 UI에서 버튼 클릭 후 응답 기다리는 동안 UI가 멈추면 안 될 때

**예시**: fetch API, setTimeout, 데이터베이스 쿼리, 파일 시스템 작업

---

## 실제 선택 기준

| 상황 | 동기 | 비동기 |
|------|------|--------|
| CPU 연산 (1ms 이내) | ✅ | ❌ |
| 네트워크 요청 | ❌ | ✅ |
| 파일 I/O | ❌ | ✅ |
| 순서 의존성 | ✅ | △ |
| UI 메인 스레드 | ❌ | ✅ |

**핵심**: 대기 시간이 있으면 비동기, 빠르게 끝나면 동기로 선택하면 됩니다.
